Windows Server Checklist

Role-aware Server hardening. Tap an item to check it off; progress is saved on this device.

Competition images have specific scoring requirements. Read the README, forensics questions, and role description first. Do not remove required roles, accounts, services, shares, or scoring tools.

0 of 0 done
  1. Establish a safe baseline
    1. Confirm server name, version, time, network settings, and whether it is a domain controller or member server.
    2. Read all competition instructions and record required users, software, roles, ports, and services.
    3. Save a VM snapshot or other approved recovery point before high-impact changes.
    4. Prioritize clear scoring requirements and critical exposures; make one change at a time and verify it.
  2. Updates and protection
    1. Install supported Windows and security updates; restart as needed and verify update status.
    2. Check Microsoft Defender status, signatures, real-time protection, and Protection History.
    3. Review exclusions and quarantine; remove unauthorized exclusions without deleting required competition files.
    4. Run a scan early enough to investigate findings and confirm critical services still work.
  3. Accounts and privileged groups
    1. Compare local and domain users with the README; investigate unknown, disabled, and stale accounts.
    2. Disable unauthorized accounts and Guest; handle built-in Administrator only as scoring rules permit.
    3. Remove unapproved users from local Administrators, Domain Admins, and other privileged groups.
    4. Do not remove service accounts, the scoring account, or required administrators without confirming their purpose.
    5. Use unique strong passwords; change known or weak passwords as directed and avoid locking out required accounts.
  4. Password, lockout, and audit policy
    1. Review effective domain/local policy and compare it with the scoring requirements before editing.
    2. Set password length, history, age, complexity, and lockout thresholds to the required values.
    3. Enable only the required advanced audit categories; avoid conflicting basic and advanced policy settings.
    4. Use Group Policy Results to confirm which policy actually applies after changes.
  5. Roles, features, and services
    1. Inventory installed roles and features; preserve required AD DS, DNS, DHCP, IIS, file, print, or other roles.
    2. Review services and startup type; disable only services confirmed unnecessary for this server role.
    3. Remove unauthorized software and features; preserve the competition scoring engine and required tools.
    4. Disable legacy or unnecessary components such as SMB 1.0 or Telnet only after confirming no requirement depends on them.
  6. Firewall and network exposure
    1. Keep Windows Firewall enabled for every profile; inspect effective inbound and outbound rules.
    2. Remove unauthorized broad allow rules and restrict legitimate management access to trusted networks.
    3. Allow only role-required ports and protocols; do not blindly block DNS, domain, web, file, or scoring traffic.
    4. Review listening ports and correlate each listener with a known service and approved role.
  7. Remote administration
    1. Restrict RDP to approved users and trusted networks; enable Network Level Authentication when supported.
    2. Keep RDP disabled only if it is not required; verify an alternate management path before changing remote settings.
    3. Restrict WinRM and PowerShell remoting to authorized administrators and networks; disable unused endpoints.
    4. Review remote logons and recent authentication events for unauthorized access.
  8. Active Directory and domain controllers
    1. Inspect privileged groups, user accounts, service accounts, and recent account changes against competition requirements.
    2. Review Group Policy links, scope, and startup scripts; remove only clearly unauthorized policies or scripts.
    3. Check domain controller health, DNS configuration, and replication status before making directory-wide changes.
    4. Do not disable AD DS, DNS, Kerberos, LDAP, or domain security features on a required domain controller.
  9. SMB, shares, and file permissions
    1. Inventory shares and their permissions; remove unauthorized shares and anonymous/guest access.
    2. Check NTFS permissions for sensitive folders and ensure only authorized users have write or administrative access.
    3. Keep SMB 2/3 for required file and domain functions; disable SMB 1 only when not required.
    4. Review SMB signing and encryption settings against the server role and competition requirements.
  10. IIS and application roles
    1. If IIS is required, review sites, bindings, application pools, modules, and virtual directories.
    2. Remove default/sample content and unauthorized sites; preserve required competition content.
    3. Use least-privilege application pool identities and restrict write permissions to necessary paths.
    4. Keep web services stopped only when the image does not require them; verify the site after changes.
  11. Persistence, logs, and final verification
    1. Review scheduled tasks, startup entries, services, PowerShell profiles, and logon scripts for unauthorized changes.
    2. Inspect Event Viewer security, system, Defender, and role-specific logs; preserve evidence of suspicious activity.
    3. Check hosts file, installed applications, local security settings, and file permissions for unauthorized modifications.
    4. Recheck scoring requirements, firewall profiles, required services, and connectivity after changes.
    5. Record unresolved findings and avoid last-minute changes that could disrupt a required server role.
