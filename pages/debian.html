Debian Checklist

Debian-focused system hardening. Tap an item to check it off; progress is saved on this device.

Read the README and forensics questions first. Preserve required users, packages, services, ports, and scoring tools. Keep a working console or recovery path before changing SSH or firewall settings.

0 of 0 done
  1. Baseline and investigation
    1. Confirm Debian release, hostname, network configuration, current user, and competition role.
    2. Read required tasks, permitted-user lists, prohibited software, and required services before changes.
    3. Record current state and create an approved snapshot or backup if available.
    4. Inspect suspicious processes and persistence before removing files; preserve evidence when appropriate.
  2. Updates and package sources
    1. Review /etc/apt/sources.list and files under /etc/apt/sources.list.d for approved Debian repositories.
    2. Remove unauthorized repositories and signing keys; do not add untrusted package sources.
    3. Refresh package metadata and review available security updates.
    4. Simulate a full upgrade before applying it; review removals and preserve required roles and scoring software.
    5. Check for unsupported releases or packages and follow competition instructions rather than changing release repositories.
  3. Users, groups, and sudo
    1. Compare local accounts and groups with the README; investigate unexpected accounts and UID 0 users.
    2. Disable or remove only unauthorized accounts; do not remove required users or service accounts.
    3. Review sudo group membership and /etc/sudoers.d; keep administrator access limited to approved users.
    4. Check password hashes and account status; set strong passwords for required interactive users.
    5. Review password quality, aging, and lockout controls; avoid edits that could lock out required competition accounts.
  4. SSH and remote access
    1. Inspect effective sshd configuration, including included files, before editing.
    2. Disable direct root SSH login when not required; use authorized individual accounts and least privilege.
    3. Review authorized_keys for every user and remove only keys confirmed unauthorized.
    4. Use key-based access where required; if password login is needed for competition, retain it as instructed.
    5. Validate configuration before reload and keep a local console session open until remote access is verified.
  5. Firewall and network
    1. Inspect listening sockets and map them to expected services and the README.
    2. Use the firewall already supported by the image; inspect existing rules before adding or removing rules.
    3. Allow required management and competition traffic before enabling or tightening a firewall remotely.
    4. Remove unauthorized listeners and broad rules; do not block required DNS, web, SSH, or scoring traffic.
    5. Review network interfaces, routes, DNS, and /etc/hosts for unauthorized changes.
  6. Services and systemd
    1. Inventory enabled services, active processes, sockets, and systemd timers.
    2. Confirm each server role (such as web, DNS, file sharing, or SSH) before disabling its services.
    3. Disable only clearly unnecessary or unauthorized services; recheck dependent services after changes.
    4. Review cron jobs, systemd units, and service overrides for unexpected commands or modified executables.
  7. Permissions and system integrity
    1. Verify ownership and permissions of /etc/passwd, /etc/shadow, /etc/group, and /etc/sudoers.
    2. Review unauthorized SUID/SGID programs and world-writable locations; investigate before changing package-owned files.
    3. Check /tmp, /var/tmp, home directories, SSH directories, and web roots for unsafe permissions or unexpected files.
    4. Review kernel modules and boot configuration only when relevant; do not apply hardening settings that prevent boot.
  8. AppArmor, logging, and time
    1. Check AppArmor status and profiles; keep enforcement enabled for required profiles where supported.
    2. Review authentication, system, package, and service logs for suspicious logins or changes.
    3. Ensure logging is active and logs are not world-writable or unexpectedly cleared.
    4. Check system time and time synchronization; preserve any required competition time settings.
  9. Applications and persistence
    1. Compare installed packages with the permitted software list; remove unauthorized programs carefully.
    2. Inspect shell startup files, profile scripts, cron locations, SSH keys, and systemd units.
    3. Review browser and remote-access software if installed; remove unauthorized extensions or tools.
    4. Check the hosts file, executable paths, and package integrity for unauthorized modifications.
  10. Final verification
    1. Recheck required users, sudo access, network connectivity, listening services, and firewall rules.
    2. Confirm SSH and any required application role still work after configuration changes.
    3. Review remaining scoring tasks and rerun checks after updates or restarts.
    4. Document unresolved findings and avoid broad recursive permission changes or unreviewed cleanup scripts.
  11. Quick commands
    1. cat /etc/os-release
    2. hostnamectl
    3. id
    4. getent passwd
    5. getent group sudo
    6. sudo -l
    7. apt list --upgradable
    8. sudo apt -s full-upgrade
    9. systemctl --type=service --state=running
    10. systemctl list-timers
    11. ss -tulpn
    12. sudo nft list ruleset
    13. sudo ufw status verbose
    14. sudo aa-status
    15. sudo journalctl -p warning -b
    16. sudo sshd -t
